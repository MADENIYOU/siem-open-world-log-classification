## (b) Ce que la littérature établit et ne dit pas, par axe

### Axe 1 : logs, gabarits nouveaux, peu d'exemples
Établi (résumés lus) :
- Les méthodes entraînées perdent beaucoup sur des logs jamais vus : jusqu'à 62,5 % en ligne selon R2. R27 traite explicitement les logs « instables » (gabarits qui changent). R28 montre qu'avec peu de lignes étiquetées par gabarit, un petit routeur généralise à des EventID jamais vus (97,7 % des anomalies sur BGL).
- La voie dominante pour le transfert est : représentation indépendante du système (R24), mélange petit modèle + LLM (R25, R27), récupération de démonstrations pour un LLM (R26). Les LLM en prompt sans entraînement rivalisent avec des modèles entraînés sur des milliers de logs (R2).
- Le pré-entraînement sur d'autres systèmes n'est pas toujours utile (R31).
Ne dit pas :
- Aucun de ces articles ne mesure la CLASSIFICATION MULTI-CLASSES par famille ECS avec des groupes de gabarits disjoints. Tous traitent l'anomalie (binaire) ou le parsing. Aucun score plafond comparable à notre 0,50 de macro-F1 n'existe dans les sources lues : non vérifié.
- Les LLM de ces articles sont grands (non exécutables localement sur un M3 Pro dans les conditions de ces papiers) ; les résultats ne se transposent pas à DistilBERT.

### Axe 2 : monde ouvert / OOD en texte
Établi :
- En texte d'intentions, les méthodes qui aident AVEC du travail sur la représentation ou des pseudo-inconnus : perte contrastive supervisée (R9), mélange gaussien avec sémantique de classe (R8), pseudo-inconnus synthétisés (R7, R10). R7 supprime le besoin de seuil.
- CLINC150 (R11) : les classifieurs détectent mal le hors-périmètre ; c'est cohérent avec notre AUROC proche de 0,6.
- Hiérarchie : ProHOC (R17), SemiHOC (R18), BOUND (R19) placent l'inconnu dans un nœud interne. Cela transforme la question « est-ce inconnu ? » en « de quelle famille ? », proche de notre constat que la confiance sur la FAMILLE bat le MSP de +0,04.
Ne dit pas :
- Les trois travaux hiérarchiques lus sont en vision ; pour le texte, seul HOCM existe et il n'a pas pu être lu. Les chiffres de R7-R9 ne sont pas dans les résumés : on ne peut pas dire de combien ils battent le MSP.
- Aucune de ces sources n'évalue avec des gabarits disjoints : les intentions de CLINC sont des phrases variées, pas des gabarits à structure fixe.

### Axe 3 : très peu d'exemples par classe
Établi :
- SetFit (R1), perte contrastive supervisée pour affinage (R12), prompts + démonstrations (R13) : meilleurs que l'affinage standard en peu d'exemples (R13 : +11 % en moyenne ; R12 : gains en few-shot).
- Zéro-coup par NLI (R3) : permet de classer à partir du nom/description de classe, sans exemple.
- Augmentations : EDA (R4, ≈ équivalent à 2x plus de données sur petits jeux), AEDA (R5), MixUp (R6).
- Kumar et al. (R14) : sonde linéaire puis affinage (LP-FT) préserve mieux les features pré-entraînées sous décalage fort.
Ne dit pas :
- Que ces méthodes aident quand un gabarit ENTIER est nouveau : les augmentations EDA/AEDA perturbent la surface d'un texte, elles ne créent pas de gabarits nouveaux. Aucune des sources lues n'étudie des textes générés par gabarit.
- SetFit exige un Sentence Transformer ; nous n'en avons pas en local. Possibilité de télécharger un petit modèle (taille et disponibilité non vérifiées) ; sinon l'idée contrastive peut être faite sur DistilBERT.

### Axe 4 : robustesse adversariale et calibration
Établi dans cette ronde : peu de nouveautés. CANINE (R23) est un encodeur sans vocabulaire, donc insensible aux problèmes de tokenisation, mais sa robustesse aux homoglyphes n'est pas dans le résumé. La conformal sous décalage de covariables (R15) existe (pondération par rapport de vraisemblance), ce qui explique pourquoi notre conformal simple donne de grands ensembles : l'hypothèse d'échangeabilité est violée par les gabarits disjoints.
Ne dit pas : si la pondération de R15 est utilisable quand les supports ne se recouvrent pas (cas des gabarits disjoints) ; non vérifié et probablement non.

### Axe 5 : évaluation
Établi :
- Les découpages aléatoires sont optimistes ; il faut plusieurs découpages biaisés ou plusieurs jeux de test indépendants (R21). Notre découpage par groupes de gabarits va dans ce sens.
- La fuite train/test gonfle les scores (R22).
- Sélection de modèle : en généralisation de domaine, un ERM bien réglé égale les méthodes sophistiquées (R20) ; cela fait écho à notre plafond commun de 19 classifieurs.
Ne dit pas : de test statistique spécifique ; les tests (Demšar, Dietterich, Benavoli) sont dans `sources_v3_stats_repro.md`.

### Axe 6 : données et plafonds
Établi : R11 (CLINC150) comme jeu de référence OOD textuel ; R30-R32 pour Loghub-2.0 et la fuite possible vers les LLM. Ne dit pas : aucun jeu public de logs étiqueté par familles ECS n'est apparu dans les pages lues ; scores plafonds en cross-template pour de la classification multi-classes : non vérifié.

## (d) Méthodes déconseillées ou qui échouent dans des conditions voisines

- **Raffinements de détection OOD post-hoc** (Mahalanobis, kNN, ViM, ASH, DICE...) : déjà constatés non meilleurs que le MSP chez nous ; Kuan & Mueller (2207.03820) et Fort (2106.03004), déjà dans les fichiers précédents, vont dans le même sens. Cette ronde n'ajoute aucune source nouvelle qui les réhabilite.
- **Pré-entraînement sur logs d'autres systèmes pris comme acquis** : R31 observe un effet incohérent (amélioration pour Flan-T5-base, perte de presque 55 % de précision de groupe pour LLaMA).
- **Affinage complet sous fort décalage** : R14 le donne moins bon que la sonde linéaire hors distribution quand les features pré-entraînées sont bonnes (à confirmer pour notre cas).
- **Découpages aléatoires** : optimistes (R21) ; fuite de gabarit gonflant les scores (R22). Les résultats sur logs « nouveaux » mais gabarits connus ne prédisent pas ceux sur gabarits nouveaux.
- **Conformal standard sous décalage** : valide seulement sous échangeabilité ; la version pondérée (R15) demande un rapport de vraisemblance estimable, ce qui est difficile avec des supports disjoints (raisonnement personnel, non vérifié par la source).
- **Transposition directe de résultats vision** (R16 CSI, R17 ProHOC, R18, R19) : la source ne donne aucun résultat en texte. À traiter comme idée, non comme preuve.
- **Résultats des LLM sur Loghub** : prudence, possible fuite de pré-entraînement (vue seulement dans des résultats de recherche, non ouverts ; R32 est la revue à ouvrir en entier pour trancher).
